# AI Reflection

One moment where the AI got something wrong was in the type annotations used in test_fuzz.py. The code ran and all the tests passed, but I noticed red underlines in the editor that the AI had missed. This made me question whether the passing tests were giving us the full picture. I raised the warnings with the AI, and running the type checkers (mypy and pyright) identified four additional issues.

What stood out to me was that the code could work during testing while still having incorrect declared types. For example, a function declared its parameter as `bytes` (which can't be changed) and then reused the same name for an editable `bytearray`. It worked when run, but the type checkers flagged every line that changed it. Python does not normally enforce type annotations at runtime, so these mistakes did not necessarily cause the tests to fail. However, incorrect annotations make the code harder to understand and can create confusion when making changes later. This helped me understand why automated tests and type checking are useful together: they check different aspects of the code.

After the issues were fixed, type checking was added to CI so it would run on every push. This meant that catching similar problems would no longer depend only on someone noticing warnings in their editor. For me, the useful outcome was not just correcting the mistakes, but improving the process that allowed them to be missed in the first place.

Another example was a test the AI wrote for a UTF-8 issue involving standard input. The original test passed on Windows by coincidence, without actually exposing the bug it was supposed to catch. The test was rewritten so that it failed against the broken implementation before checking the fix. This gave us stronger evidence that the test covered the problem and could catch it if it returned.

These experiences showed me that I need to review both the code and the tests produced by AI. A passing test is only useful if it checks the intended behaviour, and a successful test run does not mean every aspect of the code is correct. My main takeaway is to stay involved, investigate warnings, and ask what evidence supports the AI’s conclusion that something is working. Going forward, I would introduce type checking earlier and check that tests for bug fixes can actually reproduce the original failure.
